CLI and coding agents

Connect to the running app Render from a project file Give a coding agent one musical task Live-code a beat from a text file

Connect to the running app

  1. Launch the desktop app once. Open a new terminal and run synkopa status. If the shell cannot find it, open File → Settings… → Audio and scroll to Command line to check the launcher path.
  2. Open the project you want to work on. Run synkopa context --pretty to find the current revision, tracks, inserts, patterns, and channel IDs. If more than one app is running, use synkopa sessions and pass --session ID.
  3. Run one edit with a value that differs from the current project. Check that the app changed, then undo the edit by pressing Ctrl + Z or running synkopa undo.
synkopa status
        synkopa context --pretty
        synkopa bpm 128
        synkopa undo

The default target is the open project. Edits are undoable there and you decide when to save. JSON goes to stdout, messages go to stderr.

Render from a project file

  1. Use an unused filename in a scratch folder. Create a demo project and render it to a WAV without opening the app. This is a headless render.
  2. Listen to the WAV. Read the JSON render result for peaks and clipping. If it reports missing sources, fix the links or use a portable project.
  3. For a variation, use --save-as on the edit to keep the source project. Render the new file to a different WAV and compare.
synkopa new walkthrough.synkopa --template demo
        synkopa -p walkthrough.synkopa render --out walkthrough.wav
        synkopa -p walkthrough.synkopa bpm 144 --save-as faster.synkopa
        synkopa -p faster.synkopa render --out faster.wav

-p edits write back to the project unless you use --dry-run or --save-as. If the app already has that project open, use the live CLI or close the file before editing it on disk. Offline playback means rendering to a file.

Give a coding agent one musical task

  1. Start the app, open a saved project, and start your agent in a folder where it can render previews. Ask it to run synkopa context --pretty and identify the correct pattern and channel before editing.
  2. Give it a bounded goal, such as making one hi-hat pattern less repetitive. Ask it to preview a single reversible change first. For a batch of edits it can inspect synkopa schema and use apply --file for one atomic edit.
  3. Ask it to use --if-revision with the revision just inspected. On REVISION_CONFLICT, it should read the current project again before deciding how to proceed.
  4. Have it render a preview WAV and report peaks or clipping. Listen and compare with undo in the app. Save only the version you want.

Use synkopa catalog for valid effects, parameter IDs and ranges. The complete CLI reference includes MIDI, vocal editing, notes, chords, stems, and mixer tasks.

Live-code a beat from a text file

  1. Start a loop in the app. Save a text file with one command per line. Use IDs and channel names from synkopa context.
  2. Run synkopa watch song.txt in a terminal. In your editor, change a step or tempo and save. A successful save updates the looping project as one undo step.
  3. To remove a scripted change, delete its line and save. Watch reapplies the file from the project state at start. If you edit the project separately and get a revision conflict, restart watch from the new project state.
# song.txt (replace 1 with the pattern ID you found)
        bpm 128
        pattern --id 1 --ch hat --steps "x.x. x.x. x.x5 x.x9"

Press Ctrl + C in the terminal to stop watching. Use synkopa script song.txt to run a file once. A script edits a project file once at the end, or applies commands one by one in the live app.
